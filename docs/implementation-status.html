Distance to PRD-v1

Principal gaps and risks

Critical

Locked runtime is not the default runtime

The default routes every role to scripted behavior. Real MiniMax/Kimi cost, latency, failure handling, and the approximately 100-agent operating envelope remain unproven; the observed local run had about 83 agents.

High

Acceptance evidence trails implementation

The 39 deterministic tests prove mechanics, but shortened scripted scenarios do not establish the exact rumor, shocks, two-year lifecycle, dashboard latency, 365-day budget, Oracle latency, and replay gates.

High

Dashboard stack diverges

The API boundary is replaceable, but the current 65 KB, 925-line static page combines layout, state, rendering, and interaction. This increases maintainability, responsive, accessibility, and UI regression risk.

Medium

Completion-path polish

Interactive Stop does not auto-generate a report; weekly summaries are not synthesized; provider-native caching is unproven; and exact real-provider replay is not checksum-verified.

Ordered by PRD impact

Roadmap to PRD-v1 completion

  1. Prove the locked real-LLM operating envelope.Enable MiniMax M3 and Kimi K2.7 role routes, scale near 100 agents, capture cost/latency/failure telemetry, and finish 365 days under $200.
  2. Turn PRD gates into executable acceptance tests.Add exact rumor, shock effects, WebSocket latency, two-year lifecycle/arrival, Oracle, governor, and reconciliation-halt cases.
  3. Resolve the observatory architecture decision.Build the specified React/Vite/Tailwind/Recharts client against the existing REST/WebSocket contract with responsive, accessibility, and UI regression coverage.
  4. Close completion-path gaps.Generate reports after interactive Stop, synthesize weekly memory, prove native prompt caching, and checksum real stored-response replay.
  5. Produce lagging-success evidence.Run at least five experiment seeds, accumulate resolved Oracle forecasts, quantify emergent phenomena, verify all five shocks, and package reproducible reports/configs.
